## הוספת בורר מצב Plan / Build / Auto לתיבת הפרומפט

### משמעות המצבים
- **Plan** — ה-AI לא מייצר את המסמך/תרשים. הוא משיב בצ׳אט בלבד עם שאלות הבהרה, הצעות מבנה, ותוכן עניינים מוצע. שום artifact חדש לא נוצר/מתעדכן.
- **Build** — מצב היצירה הקיים: ה-AI מייצר/מעדכן את המסמך או התרשים ישירות לפי הבקשה, ללא שאלות מקדימות.
- **Auto** (ברירת מחדל) — ה-AI מחליט: אם הבקשה ברורה ומפורטת מספיק → מייצר ישר (Build). אם חסר מידע קריטי → שואל קודם שאלות (Plan), וביצירה הבאה ימשיך ל-Build.

### UI
ליד כפתור השליחה (משמאל לו, בתוך תיבת הפרומפט), כפתור קטן עם תווית המצב הנוכחי + חץ למטה (`ChevronDown`), שפותח `DropdownMenu` עם שלוש האפשרויות. אייקונים: `Sparkles` ל-Auto, `ListChecks` ל-Plan, `Wand2`/`Hammer` ל-Build. המצב הנבחר מודגש ב-✓.

המצב נשמר ב-`localStorage` תחת מפתח `chat-mode` כדי שיישאר עקבי בין שיחות.

### שינויים טכניים

1. **`src/routes/_authenticated/chat.$threadId.tsx`**
   - state חדש: `const [mode, setMode] = useState<"auto"|"plan"|"build">(...)` עם אתחול מ-localStorage, ו-effect ששומר.
   - להוסיף את הכפתור+תפריט לפני כפתור ה-Send (בתוך ה-`div` של תיבת הפרומפט).
   - להעביר את `mode` ל-`handleSend` → לבקשת ה-API.

2. **`src/routes/api/chat-message.ts`** (או הפונקציה שמקבלת את ההודעה מהמשתמש)
   - לקבל שדה חדש `mode` בבקשה.
   - להעביר אותו ל-orchestrator/agents.

3. **`src/agents/orchestrator/index.server.ts`**
   - אם `mode === "plan"`: לרוץ במסלול שיחתי בלבד — להחזיר תשובת טקסט עם שאלות/הצעות, **לדלג** על קריאת ה-agent שמייצר את ה-artifact.
   - אם `mode === "build"`: לדלג על שלב שאלות הבהרה ולהריץ ישר את ה-agent היוצר.
   - אם `mode === "auto"`: ההתנהגות הקיימת (heuristic / החלטת המודל אם לשאול קודם או לייצר).
   - בפועל זה יתורגם להזרקת הוראה ב-system prompt + flag שמכבה את שלב ה-artifact generation במצב plan.
