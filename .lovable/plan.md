# תוכנית: תמלול ישיבות עם ElevenLabs Scribe

## מה נבנה

הוספת שלב תמלול אודיו לקובייה **"תמלול וסיכום ישיבה"**. המשתמש יוכל:
1. **להקליט ישירות בדפדפן** (מיקרופון) — מתאים לישיבות קצרות / הקלטה חיה.
2. **להעלות קובץ אודיו קיים** (mp3/m4a/wav/webm, עד ~100MB) — מתאים לישיבות מוקלטות מ-Zoom/Teams/טלפון.

האודיו יישלח ל-ElevenLabs Scribe v2 דרך server function, יחזור תמלול בעברית עם **זיהוי דוברים** (Speaker 1/2/3...) ו**חותמות זמן**, והתמלול ייכנס אוטומטית כקלט לסוכן הסיכום הקיים שמייצר את המסמך הסופי (החלטות, משימות, נקודות מפתח).

## חוויית המשתמש

## ארכיטקטורה

```text
Browser                       Server (TanStack)               ElevenLabs
─────────                     ────────────────                ──────────
MediaRecorder ──▶ Blob ──▶  POST /api/transcribe-audio
   או                          (multipart)
<input type=file>                  │
                                   │  fetch(api.elevenlabs.io/v1/speech-to-text)
                                   │     model_id=scribe_v2
                                   │     language_code=heb
                                   │     diarize=true
                                   │     tag_audio_events=true
                                   │                       ──▶
                                   │                       ◀── { text, words[], speakers }
                                   ▼
                              פורמט לטקסט עם תיוג דוברים
                                   │
Transcript ◀───────────────────────┘
   │
   │  עריכה ידנית (אופציונלי)
   ▼
שליחה לזרימת הסיכום הקיימת של meeting_summary
```

## רכיבי קוד שיתווספו

1. **חיבור ElevenLabs כ-App Connector** (`standard_connectors--connect` עם `connector_id: "elevenlabs"`) → מסנכרן `ELEVENLABS_API_KEY` כסוד שרת. אין מה לבקש מהמשתמש להדביק ידנית.
2. **`src/routes/api/public/transcribe-audio.ts`** — server route שמקבל `multipart/form-data` עם הקובץ, קורא ל-ElevenLabs Scribe, מחזיר JSON עם `{ text, segments: [{ speaker, start, end, text }] }`. (תחת `/api/public/` כי הוא מקבל קבצים גדולים ולא נשלח דרך serverFn RPC; נאמת JWT של המשתמש בתוך ההנדלר.)
3. **`src/components/meeting/audio-recorder.tsx`** — רכיב הקלטה (MediaRecorder API) עם טיימר, כפתור הקלט/עצור, נגן השמעה.
4. **`src/components/meeting/audio-uploader.tsx`** — drag-and-drop + file picker, ולידציה (סוג קובץ, גודל מקסימלי).
5. **`src/components/meeting/transcript-editor.tsx`** — Textarea עם תצוגת דוברים, מאפשר עריכה לפני שליחה.
6. **מסך כניסה לקובייה** — נוסיף route ייעודי `src/routes/_authenticated/meeting-transcribe.tsx` שאליו תוביל הקובייה במקום ישירות לעורך/צ'אט. אחרי שהמשתמש מאשר את התמלול, נעביר את הטקסט לזרימה הקיימת של `meeting_summary` (הצ'אט/העורך הקיים יקבל אותו כקלט התחלתי).

## עלויות וגבולות

- **ElevenLabs Scribe**: ~$0.0037 לדקה (~₪0.014). ישיבת שעה ≈ ₪0.85.
- **גודל קובץ מקסימלי**: נתחיל עם 100MB (≈ ~3 שעות אודיו mp3 איכותי). אם צריך יותר, נוסיף chunking בעתיד.
- **שפה**: נשלח `language_code=heb` כברירת מחדל; נחשוף בעתיד בחירת שפה אם תהיה דרישה.
- **דיאריזציה**: מופעלת תמיד (כי זה השימוש הטיפוסי לישיבות).

## אבטחה

- ה-API key נשמר server-side בלבד (לא נחשף ללקוח).
- ה-route תחת `/api/public/` ימוגן ע"י בדיקת JWT של Supabase בתוך ההנדלר (לא משתמש פתוח לעולם).
- ולידציית קלט: בדיקת MIME type, גודל מקסימלי, סוג הרחבה — לפני שליחה ל-ElevenLabs.

## מה לא נכלל בשלב הזה (אפשר להוסיף בהמשך)

- **תמלול בזמן אמת (streaming)** — Scribe תומך בזה דרך WebSocket, אבל זה דורש UI מורכב יותר; נתחיל עם batch.
- **שיוך שמות אמיתיים לדוברים** (במקום Speaker 1/2) — אפשר בעריכה הידנית.
- **שמירת קובץ האודיו** ל-Storage — בשלב ראשון נעבד בזיכרון בלבד ולא נשמור (פרטיות + עלות storage). אם תרצה היסטוריית הקלטות נוסיף אח"כ.

## סדר עבודה

1. חיבור ה-connector של ElevenLabs (יצוץ חלון אישור).
2. בניית ה-server route לתמלול + ולידציה + auth.
3. בניית רכיבי הקלטה/העלאה/עורך תמלול.
4. שזירת המסך החדש בזרימת הקובייה `meeting_summary`.
5. בדיקה מקצה-לקצה עם קובץ אודיו עברי אמיתי.

---

**שאלה אחת לפני שמתחילים** — האם בשלב הזה מספיק **תמלול batch** (העלאה/הקלטה ואז שליחה), או שאתה רוצה גם **תמלול חי בזמן הישיבה** (תוך כדי שמדברים, מילים מופיעות על המסך)? תמלול חי דורש WebSocket ועוד יום עבודה.
