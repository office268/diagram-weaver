## מטרה
החלפת תהליך "יצירה → ביקורת → תיקון אוטומטי" הקיים בתהליך אינטראקטיבי שבו המשתמש בוחר אילו הצעות שיפור להחיל ומייצר גרסאות משופרות שוב ושוב.

## הזרימה החדשה

1. **יצירה ראשונית** — סוכן היצירה רץ ויוצר את המסמך (גרסה 1). נשמר ב-DB.
2. **ביקורת אוטומטית** — סוכן הביקורת רץ על המסמך ומחזיר הצעות שיפור, כל הצעה עם **דירוג חשיבות** (1-10). ההצעות מוצגות ממוינות יורד.
3. **בחירת הצעות** — המשתמש מסמן ב-checkbox אילו הצעות להטמיע.
4. **יצירת גרסה משופרת** — לחיצה על "צור גרסה משופרת" מפעילה שוב את סוכן היצירה עם המסמך הקודם + ההצעות שנבחרו בלבד → גרסה 2.
5. **חוזרים על 2-4** ללא הגבלה. כל גרסה נשמרת בקבוצה (group_id) ונראית בהיסטוריית הפרויקט.

## שינויים טכניים

### 1. סכמת ביקורת — הוספת חשיבות לכל הצעה
`src/lib/spec-output-schema.ts`:
- `ReviewSchema.notes` יעבור ממערך מחרוזות למערך אובייקטים: `{ id: string, text: string, importance: number (1-10) }`.
- מעבר תואם-לאחור בקריאה (אם מגיע string — לעטוף).

### 2. עדכון סוכן הביקורת
`src/routes/api/review-spec.ts`:
- עדכון ה-system prompt לדרוש: לכל הערה גם `importance` (1=שולי, 10=קריטי).
- עדכון `ReviewParseSchema` ופלט JSON להחזיר את המבנה החדש.

### 3. שדה חדש ב-DB — `review_notes` כבר קיים כ-JSONB, מתאים. אין מיגרציה.

### 4. רכיב חדש — `ReviewSuggestionsPanel`
`src/components/review-suggestions-panel.tsx`:
- מציג ציון כללי + רשימת הצעות ממוינת לפי `importance` יורד.
- כל הצעה: checkbox + badge חשיבות + טקסט.
- כפתור "צור גרסה משופרת" (מושבת אם 0 נבחרו).
- כפתור "סיים — שמור כגרסה סופית" (סוגר את תהליך השיפור).

### 5. שינוי מהותי ב-`projects.$projectId.tsx` — תהליך היצירה
- להסיר את התיקון האוטומטי (`shouldRevise` block).
- אחרי הגרסה הראשונה: שמירה + ביקורת + מעבר למצב **אינטראקטיבי** שמציג את ה-`ReviewSuggestionsPanel` לצד תצוגת המסמך.
- לחיצה על "צור גרסה משופרת":
  - קוראת ל-`/api/generate-spec` עם `previousSpec` + `reviewerNotes` = רק הטקסטים שנבחרו.
  - שומרת כגרסה חדשה תחת אותו `group_id`, `variant: "revised"`, ועם מספר רץ (v2, v3...).
  - מריצה ביקורת חדשה ומציגה הצעות חדשות. וחוזר חלילה.
- בסיום — `handlePick` ניווט לעורך.

### 6. תצוגת קבוצה בפרויקט
- כעת קבוצה יכולה להכיל יותר מ-2 גרסאות. ה-`groupsByType` כבר ממיין; להוסיף תווית "v1, v2, v3..." לפי סדר.
- ה-variant יישאר `original` לראשונה ו-`revised` לשאר; להוסיף שדה אופציונלי `version_index` או פשוט להסתמך על `created_at`.

### 7. עדכון `variant` ב-spec_documents
לא נדרשת מיגרציה — נשתמש ב-`created_at` בתוך הקבוצה כדי למספר.

### 8. מודל יחיד במקום השוואה
הזרימה החדשה אינטראקטיבית — לא הגיוני להריץ במקביל 3 מודלים. **נשנה ל-מודל יחיד** (ברירת מחדל מהגדרות, ניתן לבחור ב-Dialog "מסמך חדש"). הסרת `COMPARISON_MODELS` loop ו-`CompareState` הופך לסטייט בודד.
