
# הבעיה

בקוד הנוכחי ב-`dashboard.tsx`, `pickMut` קוראת ל-`createSpec` רק עבור המודל שהמשתמש לחץ עליו "בחר", ואז סוגרת את ה-dialog ומנווטת לעורך. התוצאות של שני המודלים האחרים נזרקות — הן לא נשמרות ב-DB ולכן לא מופיעות ברשימת המסמכים.

# הפתרון

כל מודל שמצליח להחזיר תוצאה — נשמר אוטומטית כמסמך נפרד ברגע שהוא מסיים, בלי קשר לבחירה של המשתמש. ה-dialog ההשוואה הופך לתצוגת preview של מסמכים שכבר קיימים, וכפתור "בחר" פשוט מנווט לעורך של המסמך הספציפי (במקום ליצור אותו).

# שינויים

### `src/routes/_authenticated/dashboard.tsx`

1. **שמירה אוטומטית בתוך `runModel`**: אחרי שקריאה ל-`genFn` מצליחה, להפעיל מיד `createFn` עם התוצאה. ה-state של המודל יעבור ל-`success` רק אחרי שגם השמירה הצליחה, ויכלול את ה-`id` של המסמך שנוצר (`{ status: 'success', spec, specId }`).

2. **אם השמירה נכשלת אבל ה-AI הצליח**: להציג סטטוס `error` עם הודעה מתאימה ("נוצר אך לא נשמר") — וכפתור "נסה שוב" ינסה רק את השמירה, לא יריץ שוב את ה-AI.

3. **כותרת המסמך**: להמשיך עם הקונבנציה הקיימת `${spec.title} — ${model}` כדי שיהיה ברור ברשימה איזה מודל יצר את המסמך.

4. **invalidate של רשימת המסמכים**: לקרוא ל-`qc.invalidateQueries({ queryKey: ['specs'] })` אחרי כל שמירה מוצלחת, כדי שהרשימה ברקע תתעדכן בזמן אמת.

5. **כפתור "בחר" → ניווט בלבד**: להחליף את `pickMut` בפונקציה שפשוט מנווטת ל-`/editor/$id` עם ה-`specId` שכבר נשמר. אין יותר state של `savingModel` כי השמירה כבר קרתה.

6. **סגירת ה-dialog**: המשתמש יכול לסגור את ה-dialog בלי לבחור כלום, ושלושת המסמכים יישארו ברשימה.

7. **טקסט מנחה**: לעדכן את תיאור ה-dialog כך שיובהר "כל המסמכים נשמרים אוטומטית, בחירה רק פותחת אחד מהם לעריכה".
