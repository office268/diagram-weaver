## מטרה
בעמוד עריכת המסמך — לאפשר למשתמש:
1. להזיז כל בלוק (סעיף/אזור) למעלה/למטה בעזרת כפתורי חץ.
2. לערוך את שם הסעיף (למשל "1. סקירה כללית" → טקסט חופשי).
3. השינויים נשמרים רק עבור המסמך הנוכחי (לא משפיע על מסמכים אחרים).

## הבלוקים שיוזזו/ייערכו
כל הבלוקים בעמוד, לפי הסדר הנוכחי:
- הפרומפט של המשתמש
- סקירה כללית
- מטרות
- משתמשי קצה
- דרישות פונקציונליות
- דרישות לא־פונקציונליות
- הנחות יסוד
- תרחישי שימוש
- ארכיטקטורה
- מודל נתונים
- סיכונים
- ביקורת הסוכן המבקר (אם קיימת)
- ההערות שלי

## שינויי DB (מיגרציה)
הוספת שתי עמודות חדשות ל-`spec_documents`:
- `section_order jsonb NOT NULL DEFAULT '[]'` — מערך של מזהי-בלוקים לפי הסדר הרצוי.
- `section_titles jsonb NOT NULL DEFAULT '{}'` — מפה מ-key של בלוק → כותרת מותאמת אישית.

ערך ריק = השתמש בסדר/כותרות ברירת המחדל. כך מסמכים קיימים ממשיכים לעבוד ללא שינוי.

## שינויים בקוד

**`src/lib/spec.functions.ts`**
- הוספת `sectionOrder: z.array(z.string()).max(50).optional()` ו-`sectionTitles: z.record(z.string(), z.string().max(200)).optional()` ל-schema של `updateSpec`.
- כתיבה לעמודות החדשות ב-handler.

**`src/routes/_authenticated/editor.$id.tsx`**
- הגדרת מערך קבוע `DEFAULT_SECTIONS` עם `{ key, defaultTitle }` לכל בלוק.
- State חדש: `sectionOrder: string[]`, `sectionTitles: Record<string,string>` — נטענים מה-spec, משולבים באוטו-שמירה (debounce 800ms) יחד עם שאר השדות.
- רינדור הבלוקים בלולאה לפי `sectionOrder` (במקום JSX קשיח), כל בלוק עטוף ברכיב `SectionBlock` שמקבל key + אינדקס + total.
- בכותרת כל בלוק:
  - `EditableText` (קיים בפרויקט) לעריכת שם הסעיף — שמירה ב-`sectionTitles[key]`.
  - שני כפתורי חץ (`ChevronUp`/`ChevronDown` מ-lucide) משמאל לכותרת, מחליפים מקום עם השכן ב-`sectionOrder`. מושבתים בקצוות.
- אם `sectionTitles[key]` ריק → מציג את `defaultTitle`. בלי מספור קשיח (כי הסדר משתנה) — אפשר להוסיף "#index." דינמי לפני הכותרת.
